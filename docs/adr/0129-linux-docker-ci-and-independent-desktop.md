# ADR-0129：Linux Docker CI 与独立桌面发行

- 状态：已采纳
- 日期：2026-10-29
- 关系：修订 ADR-0121、ADR-0127 的 GitHub 平台范围与发布依赖；GitLab 沿用原契约

## 背景

Docker Linux 部署的日常验证需要后端、前端、浏览器和真实容器验收。桌面 runner 的安装、测试与媒体编译独立占用时间，统一等待桌面发行会延长镜像发布。

## 决策

GitHub Test 默认只使用 Linux runner，按路径选择影响域、前端、浏览器、wheel 和镜像验收。未知范围、依赖与测试调度设施使用 Linux 全量。浏览器文件继续按实测时间分片，每个文件只执行一次；Python 任务保留契约测试，前端工具与真实浏览器分别交给专属任务。

Desktop 工作流按明确的平台入口、脚本与测试路径选择 Windows/macOS，手动入口执行两平台全量。普通应用或依赖改动不自动扩大桌面范围。所选桌面任务仍须全部成功，未取得差异时失败，不能宣称无需验证。

Test 通过可复用 Docker 工作流构建镜像并以临时数据卷冒烟；同一次 push/PR 不另起 Docker 构建。路径过滤在 job 层执行，固定的「完整验证结果」check 始终汇总必需任务，所选任务缺失、失败、取消或跳过均拒绝通过。前端、Python、浏览器与镜像可以并行。

GitHub 版本标签独立构建、冒烟并发布 Docker 镜像，保留 BuildKit 缓存和手动指定源码、选择是否发布的入口。推送的是本次冒烟通过的同一个本地镜像；不等待桌面构建、测试或 GitHub Release。主仓库版本镜像继续更新 `edge`，分叉仓库只发布指定版本标签。标签运行保持进行中的发布，不取消。

GitHub 桌面 Release 仅手动触发。master 上先完成 Windows/macOS 全量和独立制品验收；版本标签上的手动运行按同提交、成功演练、未过期 artifact 与 SHA-256 晋级原桌面文件。桌面候选不再要求 Docker artifact。GitHub 定版脚本等待包含容器验收的主线 Test，GitLab 仍等待原三平台演练。

## 后果

镜像和桌面发行可以各自成功或失败，GitHub 不提供两者的原子发布保证。Docker 标签阶段需要一次有缓存的构建与独立冒烟；失败可重试，不删除或重打版本标签。桌面制品继续保留原来的双架构、安装与更新验证能力。

本决策只调整 GitHub CI、发行依赖和交付文档，不改变真实账本、媒体、运行中的容器、网络或平台运行协议。缓存与成功的 CI 不代表生产服务已更新。
