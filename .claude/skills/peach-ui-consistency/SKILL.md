# Peach 界面一致性

最后复核：2026-10-28
证据来源：用户授权补齐缺失技能，以及项目 UI_COMPONENT_CONTRACTS、BOARD_UI 和 UI_PREVIEW。

## 维护源与范围

- 先确认目标仓库与调用方；应用、官网和演示站分别维护，不假定另外两仓已经存在或可以修改。
- React 界面复用现有 BoardUI 与 Peach 组合件；遗留 DOM 使用 ui-kit。组件、颜色和尺寸按目标仓库的 `docs/UI_COMPONENT_CONTRACTS.md` 与 `docs/BOARD_UI.md`。
- 修改源码后通过项目入口构建，不直接修改生成文件或 vendored 上游组件；不为同步界面复制业务逻辑。
- 共享组件变更检查所有调用方；应用功能不扩展为官网或演示站改版。跨仓同步分别记录实际变更与验证状态。

## 文案与交互

- 保留既有层级、响应式布局、控件语义和键盘操作；相同动作复用相同控件。
- 多语言翻译界面文案与可访问名称，保留 API、存储键、来源原文和馆藏事实；语言选择有明确名称并保持已选状态。
- 加载、空态、失败和保存行为按组件契约，不用假数据或隐藏错误制造完成状态。

## 预览与交付

- 按 `peach-web-ui` 与 `docs/UI_PREVIEW.md` 准备真实小样本，取得来源检查成功后提供普通和 edit 链接。
- 界面回归前遵循已有的用户预览确认要求；本技能不新增审批。
- 有布局影响时查看桌面与 390×844、深浅主题和必要交互状态，分别报告已验证、未取得和生产状态。
- 不改真实账本、媒体、凭据或其他服务；测试与预览使用独立数据和本任务进程。
